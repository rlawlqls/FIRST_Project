pull로 GitHub의 최신 변경을 가져옵니다
기본 실습
# 내 수정은 먼저 커밋한 상태
# main에서 새 작업을 시작하기 전

git switch main
git status
# nothing to commit, working tree clean

git pull --ff-only
# GitHub의 새 커밋을 로컬에 반영
push와 방향이 반대
push는 내 커밋을 보내고, pull은 원격의 변경을 가져와 현재 브랜치에 반영합니다.
시작 전에 최신 상태로
동료가 작업했거나 웹에서 PR을 병합했다면 로컬 파일은 아직 예전 상태일 수 있습니다.
--ff-only로 단순 갱신
양쪽 이력이 갈라지면 중단합니다. 이때 명령을 반복하기보다 메시지를 읽고 강사와 함께 정리합니다.

수정한 파일이 남아 있는지 status로 봅니다. 오류 메시지를 함께 기록해 도움을 요청합니다.
덮어쓰기보다 내용 비교
강제 push로 해결하려 하지 않습니다. 처음에는 강사와 함께 변경을 합친 뒤 다시 보냅니다.

WEEK 02 / Git 기초
git push -u origin feature/title을 나누어 읽기
Git 개념 · 코드로 읽기
git push -u origin feature/title
#        │  │      └─ 보낼 로컬 브랜치
#        │  └─ 원격 저장소의 별명
#        └─ upstream 연결 설정

# 연결 상태 보기
git branch -vv

# 일반적인 설정에서는 이후 같은 브랜치에서
git push
# 인자를 생략해 연결된 원격 브랜치로 전송
push는 커밋을 전송
저장하거나 add만 한 변경은 전송되지 않습니다. 먼저 보낼 브랜치에 커밋이 있어야 합니다.
-u는 연결을 기억
성공적으로 게시한 브랜치에 upstream을 설정합니다. 이후 상태 비교와 기본 push·pull에 사용됩니다.
PR과 배포는 별도 흐름
push했다고 PR이 자동 생성되지는 않습니다. 배포 자동화가 설정되어 있다면 push가 배포를 시작할 수 있습니다.
